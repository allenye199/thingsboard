# ThingsBoard多租户菜单系统说明

## 菜单系统架构解析

ThingsBoard的菜单系统分为两个层面：

1. **系统级菜单结构**: 定义在`menu.models.ts`中的菜单结构
2. **租户级别仪表板**: 通过标签与菜单项关联的仪表板内容

当您在系统中创建新的租户(Tenant)或客户(Customer)时，菜单系统的变化情况如下：

### 创建新租户时菜单系统变化

新租户创建后，系统会自动应用以下菜单设置：

1. **菜单结构不需要修改**: 所有租户共享相同的菜单结构，这部分是系统级配置。
   - `menu.models.ts`中定义的菜单项对所有租户是相同的
   - 菜单的图标、顺序、层级关系都是统一的

2. **仪表板内容需要复制**: 需要将模板租户的仪表板复制给新租户。
   - 使用上方提供的脚本可以将仪表板从一个租户复制到另一个租户
   - 确保仪表板维持相同的标签，尤其是`menu:xxx`格式的菜单标签

### 创建新客户(猪场)时菜单系统变化

新客户(Customer)创建后，系统会应用以下设置：

1. **菜单结构不需要修改**: 所有客户共享相同的菜单结构。
   - Customer用户看到的菜单项由`menu.models.ts`中的`authority: Authority.CUSTOMER_USER`项决定
   - 不同客户的管理员看到相同的菜单结构

2. **仪表板内容需要创建**: 需要为每个新客户创建相关仪表板。
   - 可以通过API或自定义动作按钮为新客户创建默认仪表板
   - 确保为这些仪表板添加正确的菜单标签(例如`menu:pigfarm`)

## 最佳实践

### 1. 使用标签系统与菜单关联

为确保菜单项在多租户环境中正确关联到相应仪表板：

```typescript
// 菜单配置示例
{
  id: 'pigfarm',
  name: '猪场管理',
  type: 'link',
  path: '/dashboard-by-tag/menu:pigfarm', // 使用标签关联
  icon: 'business',
  authority: Authority.CUSTOMER_USER
}
```

### 2. 自动化租户内容创建

在创建新租户后，使用自动化脚本执行以下操作：

1. 复制所有模板仪表板，确保保留所有标签
2. 为新租户配置默认实体（设备、资产）
3. 确保创建必要的关系和权限

### 3. 处理客户特定页面

对于客户特定的仪表板（如猪场详情页面），可使用自动创建脚本：

```javascript
// 创建客户特定仪表板的代码示例
function createCustomerSpecificDashboards(customerId) {
  // 1. 复制模板仪表板
  const dashboardData = {...模板仪表板数据};
  
  // 2. 修改仪表板以关联特定客户
  dashboardData.title = `${customerName} 详情`;
  dashboardData.configuration = JSON.stringify({
    // 仪表板配置，包括实体别名
    entityAliases: {
      "thisCustomer": {
        filter: {
          entityType: "CUSTOMER",
          id: customerId
        }
      }
    }
  });
  
  // 3. 保存仪表板并分配给客户
  // ...保存代码...
}
```

## 总结

在ThingsBoard多租户环境中，您只需修改一次菜单结构代码，所有租户和客户将共享相同的菜单架构。对于新租户和客户，主要任务是创建和分配正确标记的仪表板，而不是修改菜单系统本身。

通过使用标签系统和适当的自动化脚本，您可以实现统一的菜单体验，同时为每个租户和客户提供独立的内容。
